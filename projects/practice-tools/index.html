1 · malloc / free Logger (LD_PRELOAD)

LD_PRELOAD dlsym interposition shared library

This came directly out of the linker security model notes I was writing. I understood the theory of LD_PRELOAD — the dynamic linker searches your preloaded library before libc, so you can shadow any symbol — but I wanted to actually build it and see what breaks. So I did.

The idea is simple: compile a shared library that defines its own malloc, free, realloc, and calloc. Each wrapper grabs the real libc function via dlsym(RTLD_NEXT, "malloc"), calls it, logs the call to stdout, and returns the result. Then you preload it with LD_PRELOAD=./logger.so ./some_program and you get a full trace of every heap allocation the program makes, without touching its source. 

# build
gcc -shared -fPIC -o logger.so logger.c -ldl

# run against anything
LD_PRELOAD=./logger.so ls
LD_PRELOAD=./logger.so ./tmp

The calloc bootstrap problem

The interesting part was calloc. dlsym itself internally calls calloc before it returns — so when my calloc wrapper runs and tries to call dlsym(RTLD_NEXT, "calloc") to find the real calloc, dlsym calls back into my calloc again, which tries to call dlsym again, and you get infinite recursion and a segfault. Classic bootstrapping problem.

The fix is a small static fallback buffer. If dlsym calls calloc before real_calloc has been resolved yet, instead of recursing, you serve the allocation from a 512-byte static char array on the first call. Once dlsym finishes and returns the real calloc, all future calls go through the real one normally. I also added a __builtin_mul_overflow check on the fallback path since it's doing manual size arithmetic. 

void *calloc(size_t total, size_t size)
{
    static void *(*real_calloc)(size_t, size_t) = NULL;
    static int in_dlsym = 0;

    if (!real_calloc)
    {
        if (in_dlsym)
        {
            /* dlsym called us before we resolved real_calloc.
               serve from a static fallback buffer instead of recursing. */
            static size_t used = 0;
            static char fallback[512];

            size_t bytes;
            if (__builtin_mul_overflow(total, size, &bytes))
                return NULL;
            if (used + bytes > sizeof(fallback))
                return NULL;

            void *p = fallback + used;
            used += bytes;
            memset(p, 0, bytes);
            return p;
        }
        in_dlsym = 1;
        real_calloc = dlsym(RTLD_NEXT, "calloc");
        in_dlsym = 0;
    }

    void *tmp = real_calloc(total, size);
    char buf[1024] = {0};
    int n = snprintf(buf, sizeof(buf), "calloc(%zu, %zu) = %p\n", total, size, tmp);
    write(1, buf, n);
    return tmp;
}
One thing worth noting: I'm using write(1, buf, n) instead of printf for the logging. That's intentional — printf itself may call malloc internally, so using it inside a malloc wrapper risks reentrancy issues and infinite loops. write is a raw syscall, no heap involvement.
What's not done yet: I want to add tracking for double-free detection and allocation size classification (small / large / mmap'd). The logger currently just prints and returns — it doesn't maintain any state about live allocations. That's a future thing.

2 · Heap Inspector

ptmalloc2 chunk metadata tcache fastbin

After reading about glibc's heap internals (ptmalloc2), I wanted to be able to look at a live chunk and tell what state it's in — allocated, freed into tcache, freed into fastbin, or mmap'd — without just guessing. This tool does that by reading the chunk metadata directly from memory.

Every malloc chunk in ptmalloc2 has a header sitting 8–16 bytes before the pointer you get back. The header contains the chunk size in the upper bits and three flags in the low 3 bits: P (previous chunk in use), M (mmap'd), and A (non-main arena). The chunk after it also has a size field, and whether its P bit is set tells you if the current chunk is considered "in use" by the allocator. 

void inspect(void *p, void *first)
{
    uint8_t flag;
    uint64_t prev_size, size, next_size;

    size      = *(((unsigned long *)p) - 1);   /* header: 8 bytes before user ptr */
    flag      = size & 0x7;                    /* bottom 3 bits = P, M, A flags   */
    size      = size & 0xfffffffffffffff8;     /* mask off flags to get real size  */
    next_size = *(unsigned long int *)((char *)p - 16 + size + 8);

    if (flag == 0x2) { /* M bit set = mmap'd, not in the arena */ }

    if ((next_size & 0x1) == 0)
    {
        /* next chunk's P bit is clear = this chunk is freed */
    }
    /* ... tcache check by walking the tcache linked list ... */
}

The tcache check is the more interesting part. Glibc's tcache is a per-thread singly-linked list, one per size class (sizes 0x20–0x410 in steps of 0x10). The counts and entry pointers live at a fixed offset before the first allocation in the arena. To check if a chunk is in tcache, I walk the linked list for its size class and compare pointers. The safe-linking XOR that glibc adds (to detect corrupted list pointers) has to be undone manually: next = (ptr >> 12) ^ stored.

This is fragile — it relies on knowing the exact internal layout of tcache_perthread_struct, which is a glibc implementation detail. Works on the version I tested against; not guaranteed across versions. That's kind of the point though — understanding what the allocator is actually doing underneath, not just the public API.

3 · Packet Sniffer

raw sockets AF_PACKET Ethernet ARP / IPv4 / UDP / DNS

This is a packet sniffer I built on top of libmylib's networking layer. It opens a raw AF_PACKET socket on eth0, then loops reading frames directly off the wire — full Ethernet frames including the headers, before any protocol stack processing. For each frame it parses the Ethernet header, then branches on the EtherType to handle ARP (0x0806) or IPv4 (0x0800) specifically.

For IPv4 packets it goes deeper: parses the IP header to get source/destination addresses and the transport protocol, then if it's UDP it parses the UDP segment (including checksum validation with a carve-out for checksum offload on outgoing frames), and if the port is 53 it tries to parse it as DNS and prints the query/response details including A record answers. 

sudo ./sniff   # needs root for AF_PACKET

One thing I ran into: getsockname / getpeername don't tell you the interface MAC or IP for a raw socket — you have to use ioctl(SIOCGIFHWADDR) and ioctl(SIOCGIFADDR). That's what net_get_mac and net_get_ip in mylib wrap. Also, the DNS parser only handles A records (IPv4 addresses) right now — anything else gets silently skipped.

4 · ARP Scanner

ARP raw sockets LAN discovery

The ARP scanner does a /24 host discovery: takes an interface name, figures out the interface's own IP and MAC, then blasts ARP requests to every address from .1 to .254 (skipping itself), and listens for replies with a timeout. Anything that responds gets printed as <ip> is at <mac>.

The frame construction approach is efficient — it builds the full Ethernet + ARP frame once, then for each iteration just increments the last byte of the destination IP field directly in the buffer via a pointer. No re-marshaling the whole thing 254 times. 

/* build frame once */
u8 *point_last = tmp - 1;           /* pointer to last byte of target IP */
u8 mine        = *point_last;       /* our own last octet, skip it */

for (counter = 1; counter < 255; counter++)
{
    *point_last = counter;          /* mutate target IP in-place */
    if (counter == mine) continue;  /* don't ARP ourselves */
    sendto(fd, frame, total, 0, (struct sockaddr *)(&addr), sizeof(addr));
}

After the send loop, it switches to a receive loop with a 1.5 second timeout (SO_RCVTIMEO). When the timeout fires, recv returns -1 with errno == EAGAIN, which is the signal that the scan is done rather than an actual error. Anything else on -1 is a real failure.

I also built a simpler arp.c before this — same idea but hardcoded MACs and IPs, just to make sure I understood how to construct and send a raw ARP request manually before making it dynamic.

All of these are Linux-only (raw sockets, /proc, glibc internals). Built and tested on x86-64 Debian in a VM.
