Scalable Echo Server with epoll()

Moving from poll() to epoll() — Level-Triggered I/O Multiplexing in C

⬅ Back to I/O Multiplexing

November 2026 · Systems / Networking · GitHub Repo: Accessories

After writing the echo server with poll(), the next logical step was moving to epoll(). While poll() got the job done, it had a few drawbacks that started to become obvious once I wanted the server to scale cleanly.

With poll(), I had to keep a giant fixed array of file descriptors and client buffers in memory, pass the entire array to the kernel on every single turn, and then loop through the whole thing to check which sockets had events. With epoll(), the kernel maintains the interest list for you. It saves memory because you only allocate what you actually use, and it scales way better because epoll_wait() only hands back the descriptors that are actually ready.

1 · Level-Triggered by Default

By default, epoll works in level-triggered mode, so this echo server is also level-triggered.

In simple terms, level-triggered means that as long as a socket has data ready to be read, or buffer space ready to be written to, epoll_wait() will keep telling you about it every time you call it. You don't have to read every last byte out of the socket in one single frantic loop to avoid missing events (which is what edge-triggered mode forces you to do).

That keeps the program flow much simpler and less prone to subtle deadlocks, while still giving us the speed benefits of epoll.

2 · Attaching Client State via data.ptr

One of the biggest improvements over my poll() server was how client memory is managed. In poll.c, I had to allocate fixed arrays upfront like Clients[MAX_CLIENTS] and keep them synced with fds[MAX_CLIENTS].

With epoll, the event structure has a union called epoll_data_t which includes a void pointer (data.ptr). That means whenever a new client connects, I can just allocate a small client struct on the heap and attach it directly to the socket event: 

#define BUF_SPACE 1024

typedef struct
{
    int fd;
    char buf[BUF_SPACE];
    size_t len;  /* bytes currently in buf */
    size_t sent; /* how many of those were written */
} client;

int add_to_epoll_instance(int epfd, int fd, uint32_t event)
{
    struct epoll_event revent;
    revent.events = event;

    client *tmp = malloc(sizeof(client));
    if (tmp == NULL) return -1;

    tmp->fd = fd;
    tmp->len = 0;
    tmp->sent = 0;
    revent.data.ptr = tmp;  /* store pointer directly in epoll */

    if (epoll_ctl(epfd, EPOLL_CTL_ADD, fd, &revent) == -1)
    {
        free(tmp);
        return -1;
    }
    return 0;
}

When epoll_wait() returns, events[i].data.ptr gives me the exact client* pointer right away. There's no need to search through an array or maintain lookup tables.

3 · State Transitions: EPOLLIN and EPOLLOUT

Because epoll is level-triggered, we have to be careful with EPOLLOUT. Sockets are almost always writable as long as their kernel send buffers aren't full. If you leave EPOLLOUT enabled when you have nothing to send, epoll_wait() will wake up constantly in a busy loop.

So we flip the socket's state back and forth using epoll_ctl(..., EPOLL_CTL_MOD, ...): 

int change_state(int epfd, client *c, uint32_t event)
{
    struct epoll_event revent;
    revent.events = event;
    revent.data.ptr = c;
    return epoll_ctl(epfd, EPOLL_CTL_MOD, c->fd, &revent);
}

The flow goes like this:

  • When a client first connects, it starts in EPOLLIN mode.
  • When data arrives, read() fills the buffer up to c->len. Once we have bytes to echo back, we switch the socket to EPOLLOUT.
  • In EPOLLOUT mode, write() writes out c->len - c->sent bytes. If it only writes part of it, c->sent tracks where we left off.
  • Once c->sent == c->len, the whole message has been echoed. We reset sent = 0 and len = 0, and switch the socket back to EPOLLIN so it waits quietly for the next message.

4 · No More Array Compaction

In poll.c, whenever a client disconnected, I had to swap the last element of the array into the slot of the dead client and walk backwards through the loop so indices wouldn't get skipped.

With epoll, that whole headache disappears. Since each client's state is its own separate heap object referenced by data.ptr, removing a disconnected client is just three lines: 

int remove_from_epoll_instance(int epfd, client *c)
{
    int res = epoll_ctl(epfd, EPOLL_CTL_DEL, c->fd, NULL);
    close(c->fd);
    free(c);
    return res;
}

The kernel unregisters the socket from its internal list, the file descriptor is closed, and we free the client memory. No arrays to shift, no elements to swap.

5 · The Event Loop & Listener Handling

The main loop waits on epoll_wait() and iterates only over the events that actually fired: 

struct epoll_event events[MAX_SERVICE];

for (;;)
{
    int m = epoll_wait(epfd, events, MAX_SERVICE, -1);
    if (m == -1) ml_err_exit("EPOLL_WAIT: ");

    for (int i = 0; i < m; i++)
    {
        client *c = (client *)events[i].data.ptr;

        /* If the listener is ready, accept new connections */
        if (c->fd == listner_fd)
        {
            process_listner(epfd, listner_fd);
            continue;
        }

        /* Handle errors or hang-ups */
        if ((events[i].events & EPOLLERR) || (events[i].events & EPOLLHUP))
        {
            remove_from_epoll_instance(epfd, c);
            continue;
        }

        /* Read ready */
        if (events[i].events & EPOLLIN)
        {
            int n = process_client_for_reading(c);
            if (n < 0) remove_from_epoll_instance(epfd, c);
            else if (n > 0) change_state(epfd, c, EPOLLOUT);
        }

        /* Write ready */
        if (events[i].events & EPOLLOUT)
        {
            int res = process_client_for_writing(c);
            if (res < 0) remove_from_epoll_instance(epfd, c);
            else if (res == 2) change_state(epfd, c, EPOLLIN);
        }
    }
}

When the listener is ready, process_listner() drains all incoming connections in a loop until accept() returns EAGAIN or EWOULDBLOCK, marks each new socket as non-blocking with fcntl(), and adds it to the epoll instance.

takeaway Moving from poll() to epoll() cut down on all the manual bookkeeping. We got rid of the fixed static client arrays, eliminated the swap-with-last array compaction logic, and only deal with sockets that have real activity.
