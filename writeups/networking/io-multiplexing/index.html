Input-Output Multiplexing

Understanding asynchronous socket communication in networking

⬅ Writeups

Introduction

I/O multiplexing is a way for one thread to manage many I/O channels (like sockets or files) at once, instead of blocking on just one.

It lets the program wait for “which one is ready now” and process only the ready channels.

Concept

Instead of blocking on one channel or busy-polling many channels, I/O multiplexing allows a single thread to supervise multiple I/O channels simultaneously.

  • The program gives the kernel a list of file descriptors to monitor.
  • The thread blocks once inside a multiplexing syscall like select() or poll().
  • The kernel wakes the program only when one or more descriptors become ready.

Why Do We Need It?

Blocking I/O wastes the thread while waiting. Non-blocking I/O avoids blocking but can lead to busy polling.

I/O multiplexing solves both problems efficiently using a single thread.

  • Avoids one thread per socket.
  • Avoids busy polling.
